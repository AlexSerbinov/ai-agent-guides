# Review Loop: ітеративне мультиагентне код-рев'ю для Claude Code

## Що це і навіщо?

AI coding-агенти пишуть код швидко — але хто рев'юїть рев'юера? Коли AI-агент завершує задачу, вам залишається вручну перевіряти баги, безпеку та архітектурні проблеми. Це повільно і зводить нанівець переваги AI-розробки.

**Review Loop** вирішує це, запускаючи **6 паралельних агентів-рев'юерів** на ваших незакомічених змінах:

| # | Агент | Інструмент | Фокус |
|---|-------|-----------|-------|
| 1 | Загальне рев'ю #1 | Claude Code | Баги, логічні помилки, edge cases |
| 2 | Загальне рев'ю #2 | Claude Code | Незалежна друга думка |
| 3 | Ламаючі зміни | Claude Code | API контракти, регресії |
| 4 | Аудит безпеки | Claude Code | OWASP Top 10, ін'єкції, авторизація |
| 5 | Загальне рев'ю | Codex CLI | Погляд від OpenAI |
| 6 | Архітектура | Gemini CLI | Якість коду, DRY, нейменг |

Після того як всі агенти звітують, система:
1. **Агрегує** всі знахідки в єдиний дедуплікований список
2. **Оцінює** ваші зміни (0-100) за рівнями серйозності
3. **Авто-фіксить** безпечні проблеми (баги, безпека, мертвий код, відсутні типи)
4. **Перезапускає** весь цикл на виправленому коді
5. **Повторює** поки скор не досягне 95% або вище

### Що ви отримуєте:

- **Мультиперспективне рев'ю** — 6 агентів ловлять більше ніж 1
- **Крос-валідація** — якщо кілька агентів позначили ту саму проблему, вона точно реальна
- **Автоматичні фікси** — Critical/High/Medium проблеми виправляються без запиту
- **Ітеративне покращення** — кожен цикл рев'юїть актуальний стан після попередніх фіксів
- **Детальний лог** — вивід кожного агента та кожен фікс записуються в `docs/review-logs/`
- **Ніколи не комітить** — тільки рев'юїть та фіксить, ви вирішуєте коли комітити

### Чого це НЕ робить:

- Не комітить зміни (це ваше рішення)
- Не змінює бізнес-логіку (хіба що вона явно поламана)
- Не рефакторить оточуючий код (тільки мінімальні, цільові фікси)
- Не модифікує інфраструктуру (CI/CD, GitHub Secrets — тільки звітує)

## Передумови

Перед використанням Review Loop встановіть:

### 1. Codex CLI (OpenAI)

```bash
npm install -g @openai/codex
codex login
```

Перевірка:

```bash
codex --version
```

### 2. Gemini CLI (Google)

```bash
npm install -g @anthropic-ai/gemini-cli
```

Або встановіть офіційним методом від Google. Перевірка:

```bash
gemini --version
```

### 3. jq (парсинг JSON)

На macOS:

```bash
brew install jq
```

На Ubuntu/Debian:

```bash
sudo apt install jq
```

### 4. Claude Code

Review Loop працює всередині Claude Code як **скіл** (slash command). Потрібен встановлений і запущений Claude Code.

## Як налаштувати

### Спосіб 1: Автоматичний (рекомендований)

Скажіть Claude Code:

> "Налаштуй скіл Review Loop. Ось промпт: [вставте вміст prompt-ukr.md]"

Claude Code створить файл скілу в `~/.claude/skills/review-loop/SKILL.md`.

### Спосіб 2: Ручний

1. Створіть директорію скілу:

```bash
mkdir -p ~/.claude/skills/review-loop
```

2. Скопіюйте файл промпту (`prompt-ukr.md` з цього репо) в `~/.claude/skills/review-loop/SKILL.md`

3. Перезапустіть Claude Code

4. Тепер можна викликати через: `/review-loop`

### Потік виконання:

1. **Перевірка змін** — `git diff HEAD`. Немає змін? Стоп.
2. **Запуск 6 агентів паралельно** — всі одночасно, не послідовно
3. **Збір результатів** — очікування завершення всіх агентів
4. **Агрегація та дедуплікація** — об'єднання знахідок, фіксація згоди агентів
5. **Скорінг** — розрахунок якості на основі ваги серйозності
6. **Авто-фікс** — застосування безпечних фіксів (Critical/High/Medium)
7. **Цикл або стоп**:
   - Скор >= 95% → Готово, можна комітити
   - Скор < 95% і фікси застосовані → Перезапуск циклу
   - Скор < 95% і немає безпечних фіксів → Стоп, звіт про залишені проблеми
   - Максимум 5 ітерацій → Стоп в будь-якому випадку

### Система скорінгу:

| Критерій | Вага | Вирахування |
|----------|------|-------------|
| Критичні проблеми | 30% | -30 за кожну |
| Високі проблеми | 25% | -10 за кожну |
| Середні проблеми | 20% | -3 за кожну |
| Вразливості безпеки | 15% | -20 за критичну, -10 за високу |
| Архітектура/чистота | 10% | 0-10 на основі відгуків агентів |

**Скор = max(0, 100 - загальні_вирахування)**

### Що авто-фікситься:

- Баги (логічні помилки, race conditions, off-by-one, null/undefined)
- Безпека (валідація вводу, перевірки авторизації, запобігання ін'єкцій)
- Обробка помилок (null перевірки, try-catch, правильні повідомлення)
- Якість коду (невикористані імпорти, мертвий код, друкарські помилки)
- Типобезпека (відсутні типи, неправильні типи)
- Swagger анотації (відсутні @Api декоратори)

### Що НЕ авто-фікситься:

- Стилістичні переваги без конкретного бага
- Нечіткі пропозиції типу "розгляньте рефакторинг"
- Інфраструктурні зміни (GitHub Secrets, CI/CD)

## Лог рев'ю

Кожна ітерація логується в markdown файл:

```
docs/review-logs/YYYY-MM-DD-HH-MM-review-loop.md
```

Лог містить:
- **Повний сирий вивід** кожного агента (без скорочень)
- **Кожен застосований фікс** з before/after фрагментами коду
- **Скори та статистику** по кожній ітерації
- **Фінальне резюме** з кумулятивними змінами

Це ваш аудиторський слід — завжди можна повернутись і подивитись що знайшов кожен агент та що було змінено.

## FAQ

**Q: Чи потрібні всі 3 AI інструменти (Claude, Codex, Gemini)?**
A: Ні. Якщо Codex CLI або Gemini CLI не встановлені, рев'ю продовжується з рештою агентів. Мінімум 4 агенти повинні відповісти для валідної ітерації.

**Q: Скільки часу займає одна ітерація?**
A: Зазвичай 1-3 хвилини, оскільки всі 6 агентів працюють паралельно.

**Q: Чи може воно поламати мій код?**
A: Цикл робить тільки цільові, мінімальні фікси. Він ніколи не рефакторить оточуючий код і не змінює бізнес-логіку. І ніколи не комітить — ви переглядаєте зміни перед комітом.

**Q: А якщо буде нескінченний цикл?**
A: Жорсткий ліміт — 5 ітерацій. Після цього зупиняється і звітує залишені проблеми.

**Q: Чи працює з не-TypeScript проектами?**
A: Так. Агенти рев'юять будь-який код в git diff. Промпти мовно-агностичні — аналізують будь-які зміни.

**Q: Чи можна кастомізувати які агенти запускаються?**
A: Так, відредагуйте промпт скілу в `~/.claude/skills/review-loop/SKILL.md`. Можна видалити, змінити або додати агентів.

**Q: Де логи?**
A: `docs/review-logs/YYYY-MM-DD-HH-MM-review-loop.md` в корені проекту.
