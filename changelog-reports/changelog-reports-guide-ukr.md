# Автоматичне ведення Changelog та Daily Report через Claude Code

## Що це і навіщо?

Коли працюєш з AI coding-агентом, він виконує купу задач за день — фіксить баги, додає фічі, рефакторить. Але без логування ти втрачаєш контекст: що саме було зроблено, яку проблему вирішили, і чому саме так.

Ця інструкція змушує Claude Code **автоматично вести два лог-файли** після кожної задачі:

- **Changelog** (`changelog.md`) — детальний журнал з описом проблеми, рішення та деталей
- **Daily Report** (`docs/reports/YYYY-MM-DD-daily-report.md`) — короткий звіт за день у стилі стендапу

Claude Code **не зможе завершити задачу** поки не запише в обидва файли — це blocking requirement.

### Що отримуєш:
- **PM** бачить що відбувається на проекті без запитувань у девелопера
- **Девелопер** має повний лог — можна згадати що і коли робилось
- **Команда** має спільний changelog — менше конфліктів, всі в контексті
- **Стендапи** стають простіше — daily report вже написаний

## Як налаштувати

Є два способи:

### Спосіб 1: Автоматичний (дай цю інструкцію Claude Code)

Просто скажи Claude Code:

> "Налаштуй мені автоматичне логування в changelog та daily report. Ось інструкція: [вставити URL цього файлу або скопіювати Крок 1 та Крок 2 нижче]"

Claude Code сам створить/оновить `~/.claude/CLAUDE.md` з потрібним промптом.

### Спосіб 2: Ручний

Скопіюй промпт з Кроку 1 нижче в `~/.claude/CLAUDE.md`.

---

## Крок 1: Додати промпт в глобальний конфіг Claude Code

Файл: `~/.claude/CLAUDE.md`

Якщо файлу ще не існує — створи:

```bash
mkdir -p ~/.claude
touch ~/.claude/CLAUDE.md
```

Додай наступну секцію в цей файл:

````markdown
## End of Task Routine (Логування) — BLOCKING REQUIREMENT

**CRITICAL:** Ти НЕ МОЖЕШ завершити задачу поки не оновиш **ОБИДВА** лог-файли нижче. Це не опціонально — це обов'язковий крок завершення кожної задачі. Якщо завершив задачу без оновлення changelog і daily report — це помилка.

**Чекліст перед завершенням задачі (кожен раз, без винятків):**
- [ ] Записав у `changelog.md`
- [ ] Записав у `docs/reports/YYYY-MM-DD-daily-report.md`
- [ ] Тільки після цього завершую відповідь

Це робиш ти (основний агент), а не subagent — бо ти маєш повний контекст розмови і розумієш бізнес-задачу.

**Що писати:** фокусуйся на **бізнес-контексті** — яку проблему вирішували, яку задачу юзер описав, який результат. Не "змінив файл X", а "пофіксив баг з маппінгом мережі в Changee — USDT падав бо відправляли тікер без мережі".

### 1. Changelog — ОБОВ'ЯЗКОВО

Файл: `changelog.md` в корені проекту (або де він вже існує в проекті).

**Формат запису — детальний опис проблеми та рішення:**

```
## YYYY-MM-DD HH:MM — ProjectName

**Проблема:** Детально описати, яка проблема була — що не працювало, як це проявлялось, чому це було важливо. 1-2 речення.

**Рішення:** Що саме зробили для вирішення — який підхід обрали, що змінили, який результат. 1-3 речення.

**Деталі:** Додаткові нюанси — які файли/модулі зачеплено, чи впливає на фронтенд або інші сервіси, edge cases. Опціонально.
```

**Правила changelog:**
- Кожен запис — окремий `##` блок з датою, часом і назвою проекту
- Писати **бізнес-мовою** — не "змінив файл X", а "USDT свопи падали бо відправляли тікер без мережі"
- **Нова задача** → новий `##` блок
- **Продовження/допрацювання** тієї самої задачі → **додати новий `##` блок** з поміткою що це оновлення. Не редагувати попередній запис — дописувати новий, щоб була історія змін
- Якщо файл не існує — створи з заголовком `# Changelog`

**Приклад:**

```markdown
## 2026-03-18 14:35 — MyProject

**Проблема:** Changee провайдер повертав помилку при створенні ордеру на USDT. Користувачі не могли робити свопи з USDT на будь-яку іншу криптовалюту через цього провайдера.

**Рішення:** Виявили що ми відправляли тікер "USDT" без вказання мережі. Changee API вимагає формат "USDT-TRC20". Додали маппінг мереж в адаптері Changee.

**Деталі:** Зачеплено changee.adapter.ts. Впливає на фронтенд — тепер у відповіді є поле network в об'єкті валюти.

---

## 2026-03-18 15:20 — MyProject

**Оновлення до попередньої задачі (Changee USDT маппінг):** Додали маппінг ще для USDC та DAI — аналогічна проблема. Також додали unit-тести на всі мережеві маппінги.
```

### 2. Daily Report — ОБОВ'ЯЗКОВО

Файл: `docs/reports/YYYY-MM-DD-daily-report.md` в директорії проекту.

```markdown
# Звіт за DD.MM.YYYY

**Звіт:**
- Що зробив (бізнес-мовою, як для стендапу)
- Ще щось зробив
```

- Один файл на день, доповнюється протягом дня
- Bullet points, українською, неформально
- **Нова задача** → новий буллет
- **Допрацювання існуючої задачі** → оновити існуючий буллет (не створювати новий, а дописати/змінити текст)
````

## Крок 2: Перевірити що працює

Після додавання промпту в `~/.claude/CLAUDE.md`, просто дай Claude Code будь-яку задачу. Наприкінці він має:

1. Створити/оновити `changelog.md` в корені проекту
2. Створити/оновити `docs/reports/YYYY-MM-DD-daily-report.md`
3. Тільки після цього завершити відповідь

Якщо не зробив — нагадай йому: "Ти забув оновити changelog і daily report".

## Структура файлів після налаштування

```
~/.claude/CLAUDE.md              ← Твій глобальний конфіг (один на всі проекти)

your-project/
├── changelog.md                           ← Детальний журнал змін (автоматично)
├── docs/
│   └── reports/
│       ├── 2026-03-17-daily-report.md     ← Звіт за вчора
│       └── 2026-03-18-daily-report.md     ← Звіт за сьогодні
```

## FAQ

**Q: Чи потрібно створювати `changelog.md` вручну?**
A: Ні, Claude Code створить його автоматично при першій задачі.

**Q: Що якщо я працюю над кількома проектами?**
A: `~/.claude/CLAUDE.md` — глобальний, він діє на всі проекти. Changelog і daily report створюються в корені кожного проекту окремо.

**Q: Мій колега теж веде changelog — чи не буде конфліктів?**
A: Кожен запис — це окремий `##` блок. Git merge конфлікти малоймовірні, бо записи завжди додаються в кінець файлу.

**Q: Можна змінити формат?**
A: Так, промпт повністю під твоїм контролем. Зміни формат в `~/.claude/CLAUDE.md` як тобі зручно.

**Q: Працює тільки з Claude Code?**
A: Цей промпт написаний для Claude Code (`~/.claude/CLAUDE.md`), але концепцію можна адаптувати для інших AI-агентів — просто покладіть аналогічну інструкцію в їх конфіг-файл (`.cursorrules` для Cursor, `AGENTS.md` для Codex CLI).

## Сумісні агенти

| Агент | Конфіг-файл | Статус |
|-------|-------------|--------|
| Claude Code | `~/.claude/CLAUDE.md` | Повна підтримка |
| Cursor | `.cursorrules` | Потребує адаптації промпту |
| Codex CLI | `AGENTS.md` | Потребує адаптації промпту |
