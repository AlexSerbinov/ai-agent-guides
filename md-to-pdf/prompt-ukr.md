Конвертувати Markdown файл у високоякісний PDF за допомогою md-to-pdf (Puppeteer/Chrome).

## Інструкції

1. Юзер надає аргументи в `$ARGUMENTS`.
2. Розпарсити аргументи:
   - Перший аргумент: шлях до `.md` файлу (ОБОВ'ЯЗКОВИЙ)
   - Другий аргумент (опціонально): output шлях для PDF. Якщо не вказано, PDF зберігається поруч з вихідним файлом з розширенням `.pdf`.
3. Перевірити що вихідний файл існує.
4. Запустити конвертацію через Bash:
   ```
   md2pdf <input-file> [output-file]
   ```
   Встановити timeout 30000ms. Команда виводить шлях результату, розмір та час.
5. Після конвертації відкрити PDF командою `open <file.pdf>` щоб юзер побачив результат.
6. Відкрити директорію де лежить вихідний markdown файл командою `open <directory>` щоб юзер бачив всі файли.
7. Повідомити про успіх з шляхом до файлу та розміром.

## Edge cases
- Якщо юзер дав тільки ім'я файлу без шляху, резолвити відносно поточної робочої директорії.
- Якщо юзер дав директорію, шукати README.md або єдиний .md файл всередині і конвертувати його.
- Якщо юзер дав raw markdown текст замість шляху до файлу (немає розширення .md, містить пробіли/переноси рядків), зберегти у тимчасовий файл, конвертувати і повідомити output шлях.
- Якщо конвертація не вдалась, показати повідомлення помилки.

## Верифікація layout сторінок (опціонально, за запитом юзера)

Після генерації PDF перевірити що всі елементи на правильних сторінках — немає orphaned headings, немає розірваних таблиць/код-блоків, немає порожніх сторінок та сторінок з переважно білим простором (менше ~30% контенту).

### Як перевірити

1. Конвертувати PDF сторінки в зображення через `pdftoppm`:
   ```
   mkdir -p /tmp/pdf_pages && rm -f /tmp/pdf_pages/*.png
   pdftoppm -png -r 150 <output.pdf> /tmp/pdf_pages/p 2>/dev/null
   ```
   Це створить `/tmp/pdf_pages/p-01.png`, `p-02.png`, тощо.

2. Порахувати сторінки: `ls /tmp/pdf_pages/ | wc -l`

3. Переглянути кожну сторінку через Read tool на PNG файлах: `Read /tmp/pdf_pages/p-01.png`
   - Перевіряти 4-5 сторінок одночасно паралельно для швидкості.

4. Шукати ці проблеми:
   - **Orphaned heading**: заголовок внизу сторінки, контент на наступній (великий порожній простір)
   - **Split code block**: код-блок починається на одній сторінці, продовжується на наступній
   - **Split table**: заголовок таблиці на одній сторінці, рядки на наступній
   - **Empty/near-empty page**: тільки 2-3 рядки тексту, решта — білий простір
   - **Sparse page**: контент тільки у верхніх ~30%, решта порожня. Це трапляється коли примусовий page-break стоїть після короткої секції. Сторінки мають бути розумно заповнені — мінімум 50% контенту на сторінку (крім титульної та останньої)
   - **Title page issues**: зміст або контент потрапляє на титульну сторінку

### Як виправити

- **Orphaned heading**: Змінити `**Bold heading**` на `#### Heading` — CSS `h4 { page-break-after: avoid }` запобігає orphans
- **Empty page від примусового page-break**: Видалити `<div style="page-break-before: always;"></div>` перед короткими секціями
- **Sparse page**: Видалити page-break перед наступною секцією щоб контент заповнив сторінку. Використовувати примусові page-breaks тільки перед великими секціями які мають достатньо контенту щоб заповнити більшу частину наступної сторінки
- **Large code block split**: Розбити на менші код-блоки з текстом між ними
- **Large table split**: Розділити таблицю на дві менші (наприклад, P1 інструменти та P2 інструменти)
- **Content too close to page break**: Видалити page-break і дозволити контенту текти природно

### CSS для Markdown файлів (додати на початку .md файлу)

```html
<style>
table { page-break-inside: avoid; margin-bottom: 1em; }
pre { page-break-inside: avoid; }
blockquote { page-break-inside: avoid; }
h2, h3, h4 { page-break-after: avoid; orphans: 3; widows: 3; }
p { orphans: 3; widows: 3; }
li { page-break-inside: avoid; }
</style>
```

Використовувати `<div style="page-break-before: always;"></div>` тільки перед великими секціями. Не зловживати — спричиняє порожні сторінки.

### Ітерація

Після виправлення перегенерувати PDF і перевірити знову. Повторювати поки всі сторінки не будуть виглядати правильно.

## Примітки
- Chrome запускається тільки під час конвертації (~2-3 секунди) і закривається після. Жодних постійних процесів.
- Якщо `md2pdf` не знайдено, встановити: `npm install -g md-to-pdf`
- `pdftoppm` з poppler (`brew install poppler` якщо не встановлено).
